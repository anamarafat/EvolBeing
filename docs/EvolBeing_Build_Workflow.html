0. Project and installed tools

1. Initialise the x64 compiler environment

Open Command Prompt (cmd.exe). Run:

call "C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\VC\Auxiliary\Build\vcvars64.bat"

This batch file configures the current terminal session for 64-bit MSVC compilation. In particular, it sets paths to the compiler, linker, C++ standard-library headers and Windows SDK headers/libraries.

Environment variablePurpose
PATHFind tools such as cl.exe and link.exe.
INCLUDEFind C++ standard-library and Windows SDK headers.
LIBFind libraries used at link time.

Verify the compiler is accessible:

cl
You need to initialise a new ordinary Command Prompt each time. You can instead open an already-configured x64 Native Tools Command Prompt for Visual Studio.

2. Navigate to the project

cd /d C:\Dev\EvolBeing\EvolBeing_Gen_alpha

cd changes the working directory; /d also permits changing the drive. The dot (.) in the next command refers to this project directory.

3. Configure CMake

cmake -S . -B build-qt -G Ninja -DCMAKE_TOOLCHAIN_FILE=C:/Dev/vcpkg/scripts/buildsystems/vcpkg.cmake
ArgumentMeaning
-S .Read source configuration from the current directory.
-B build-qtStore generated build files in build-qt.
-G NinjaUse Ninja as the build executor.
-DCMAKE_TOOLCHAIN_FILE=...Integrate vcpkg so CMake can discover installed dependencies, including Qt.

CMake reads CMakeLists.txt and determines source files, include directories, targets, library dependencies, and compiler/linker options. It writes files such as build-qt/build.ninja and build-qt/CMakeCache.txt.

Example of the key project relationships (not necessarily your entire CMake file):

find_package(Qt6 REQUIRED COMPONENTS Widgets)

add_library(GeomCore STATIC
    src/SurfaceMesh.cpp
    src/ObjIO.cpp
)
target_include_directories(GeomCore PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/include)
target_compile_features(GeomCore PUBLIC cxx_std_20)

add_executable(EvolBeing_Gen_Alpha
    app/main.cpp
    app/MainWindow.cpp
    include/MainWindow.hpp
)
target_include_directories(EvolBeing_Gen_Alpha PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/include)
target_link_libraries(EvolBeing_Gen_Alpha PRIVATE GeomCore Qt6::Widgets)

Important: listing a header in add_executable does not automatically add its directory to the compiler search path; target_include_directories does that.

Configuration is not the normal application compilation stage. CMake may compile small test programs while detecting the compiler, but the actual project build happens next.

4. Build using Ninja and MSVC

cmake --build build-qt

CMake invokes Ninja, which executes compiler and linker commands generated in Step 3. MSVC cl.exe compiles .cpp files to machine-code .obj files; the linker link.exe combines them and their libraries.

SurfaceMesh.cpp + ObjIO.cpp

↓ compile

Object files → GeomCore.lib (static library)

+

main.cpp + MainWindow.cpp

↓ compile

Object files + GeomCore.lib + Qt import libraries

↓ link

EvolBeing_Gen_Alpha.exe

GeomCore is statically linked into the executable as needed. Qt is dynamically linked, so the Qt DLLs must be available when the application starts.

Incremental builds

After changing only a .cpp file, run cmake --build build-qt again. Ninja normally recompiles only the affected files and relinks as needed. It will also typically trigger CMake regeneration if CMakeLists.txt changes.

5. Deploy the Qt runtime (current Debug build)

We previously encountered Could not find the Qt platform plugin "windows". The executable needs Qt DLLs and a Windows platform plugin alongside it.

For your installed vcpkg layout, copy the Debug DLLs:

copy C:\Dev\vcpkg\installed\x64-windows\debug\bin\Qt6Cored.dll build-qt\
copy C:\Dev\vcpkg\installed\x64-windows\debug\bin\Qt6Guid.dll build-qt\
copy C:\Dev\vcpkg\installed\x64-windows\debug\bin\Qt6Widgetsd.dll build-qt\

Create the platform plugin directory and copy the actual located plugin:

if not exist build-qt\platforms mkdir build-qt\platforms
copy C:\Dev\vcpkg\installed\x64-windows\debug\Qt6\plugins\platforms\qwindowsd.dll build-qt\platforms\

Expected core runtime layout:

build-qt\
  EvolBeing_Gen_Alpha.exe
  Qt6Cored.dll
  Qt6Guid.dll
  Qt6Widgetsd.dll
  platforms\
    qwindowsd.dll

The trailing d means Debug. Qt uses the Windows platform plugin to integrate with native window creation and input handling. The Debug executable must use matching Debug Qt runtime components.

Deployment caveat: these files were sufficient to get your current GUI running, but additional Qt features or libraries may require further runtime dependencies. For a clean build, recopy the required files. Later, automate deployment in CMake.

Why did windeployqt fail earlier?

The deployment tool looked for Qt6Widgetsd.dll in the non-Debug bin directory, while vcpkg had placed it under debug\bin. The plugin was likewise under debug\Qt6\plugins\platforms, not debug\plugins\platforms. We therefore used the confirmed locations directly.

6. Run the GUI

.\build-qt\EvolBeing_Gen_Alpha.exe

Windows loads the executable and its dependent DLLs. Qt then locates the Windows platform plugin. Your entry point creates the application and window:

#include "MainWindow.hpp"
#include <QApplication>

int main(int argc, char* argv[])
{
    QApplication app(argc, argv);
    MainWindow window;
    window.show();
    return app.exec();
}

QApplication initialises Qt; MainWindow window constructs the GUI; window.show() displays it; and app.exec() starts the event loop, handling mouse clicks and other events until the application closes.

The working Import Mesh workflow is: button click → file picker → geom::loadOBJ() → SurfaceMesh → displayed vertex/triangle counts.

:: 3. Build changed files

:: 4. Launch the GUI
.\build-qt\EvolBeing_Gen_Alpha.exe

When do I run each command?

SituationWhat to run
Fresh ordinary terminalInitialise vcvars64.bat, then cd into the project.
Changed a .cpp or .hppcmake --build build-qt then run the executable.
Changed CMakeLists.txtUsually just build (CMake auto-regenerates); explicitly reconfigure if needed.
Deleted build-qt or configuring for the first timeRun the full CMake configure command, build, deploy Qt runtime files, then run.
Changed toolchain, architecture, or major build settingsReconfigure, often using a fresh build directory.
Only want to run an already built appRun the .exe; MSVC environment is not inherently required just to execute it if runtime dependencies are present.

8. Quick troubleshooting

SymptomLikely cause / action
cl not recognised; missing <array> or other standard headersInitialise the x64 MSVC environment before configuring/building.
Cannot open include file: 'MainWindow.hpp'Check file location and the executable's target_include_directories.
Qt includes red in VS Code, but build succeedsEditor IntelliSense issue; configure compile_commands.json later. The compiler's include paths are correct.
Could not find Qt platform plugin "windows"Ensure build-qt\platforms\qwindowsd.dll exists and the matching Debug Qt DLLs are available.
Need detailed Qt plugin diagnosticsRun set QT_DEBUG_PLUGINS=1, then launch the executable from the same terminal.
Build succeeds but no window appearsCheck that main.cpp constructs MainWindow, calls show(), and enters app.exec().
